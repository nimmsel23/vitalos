## Neuer Datenbaustein in Arbeit

`habits-dev` enthält auf `dev` (Quellstand `56ad2db`) ein versioniertes Daily-Execution-Modell mit genau vier festen Dimensionen. Die Zuweisung ist getrennt von der bestehenden Core4-Kategorie; sie erzwingt verschiedene vorhandene Habit-IDs. Ein Tag hält Name und Skill-Links als Snapshot fest, damit spätere Habit-Änderungen nicht alte Tageswerte umdeuten. Die einzige derzeitige Erfüllungsregel ist `manual`: ein ausdrücklicher Nutzer-Toggle. KI-Text, Kalender-Vorsatz oder bloße Tracker-Aktivität zählen nicht automatisch.

Die Daily-Four-Implementierung liegt inzwischen im Quellrepo `/home/alpha/dev/habits-dev` auf `dev` (aktueller Quellstand `56ad2db`):

- Commit `40f4c9d` enthält den Modellkern `src/views/Habits/dailyExecutionModel.js`: vier feste Dimensionen, verschiedene bestehende Habit-IDs, manueller Abschluss, eingefrorene Namen/Skill-Links, Tageswert maximal 4 und Sperre gegen Zuweisungsänderung nach einem Tagesabschluss oder einer Skill-Verknüpfung.
- Commit `ed8fd47` ergänzt Firestore- und UI-Fluss. Die Konfiguration liegt unter `/fitness/{uid}/settings/dailyExecution`, Tages-Snapshots unter `/fitness/{uid}/dailyExecution/{date}`. Eine manuelle Bestätigung aktualisiert den Snapshot und den zugehörigen bestehenden `habitRecords`-Datensatz in einer Firestore-Transaktion.
- Commit `0f4c163` verhindert, dass normale `habitRecords` aus Smart Logging/Altbestand beim Erzeugen eines Tages-Snapshots Punkte setzen. Commit `237e555` ergänzt die explizite Verknüpfung einer bestehenden Fitness-Session: Der Nutzer wählt im ausgeklappten Habit-Detail eine gespeicherte Session des Tages; UID-gebunden prüft eine Transaktion deren Existenz/Datum, speichert die Referenz im Snapshot und zählt die Dimension einmal. Trainingsdetails werden nicht kopiert. Commit `13247b1` ergänzt gleichartige Referenzen für Nutrition und Relax: Nutrition prüft Mahlzeiten oder Wasser im Tageslog; Relax prüft vorhandene Praxis-Einträge, auch wenn ältere Items keine ID tragen. Je Skill wird der unveränderte Tagesdatensatz referenziert; mehrere Fachdetails bleiben ein Tagespunkt.
- Das Habits-Firebase-Modul exportiert die App-Instanz, die der integrierte Journal-Smart-Logger über den bestehenden Vite-Alias verwendet. Ohne den Export schlug der gemeinsame Bundle-Build bei `smartJournalLogger.js` fehl.
- Daily Four ist die Standardansicht für eine lokale Erstinstallation. Es gibt weiter Umschalter zur bisherigen Habits- und Core4-Ansicht. Vier verschiedene vorhandene Habits werden explizit ausgewählt; alte Core4-Kategorien werden nicht automatisch umgedeutet.
- Details klappen eine optionale Skill-Verknüpfung aus. Fitness öffnet die Session-Erfassung, Planner die Plan-Ansicht, weitere Ziele Journal, Nutrition/Fuel, Relax oder Habits. Der gemeinsame Firebase-Shell-Build mit dem lokalen Daily-Four-Worktree als vorübergehendem `habit-app`-Eingang baut erfolgreich (5.655 Module; `/tmp/vos-integrated-daily-four-build` enthält den Daily-Four-Text). Danach wurde der originale Checkout wiederhergestellt. Der Shell-Gitlink zeigt weiterhin auf `09623a8`, deshalb enthalten normale Shell-Builds den neuen Stand erst nach dem vorgesehenen Release-/Gitlink-Schritt.
- Eine am aktuellen Tag bereits bestätigte oder mit Detaildaten verknüpfte Ebene verhindert, dass eine Zuweisungsänderung dessen Snapshot umschreibt. Die neue Konfiguration gilt dann ab morgen. Tage ohne Daily-Execution-Snapshot werden nicht aus alten Core4-Daten rekonstruiert.
- Normale `habitRecords` aus Altbestand, Smart Logging oder einem anderen Tracker setzen beim erstmaligen Erzeugen eines Daily-Four-Snapshots keinen Punkt. Daily Four startet für diesen Tag bei 0; ein Punkt entsteht nur über die ausdrückliche Daily-Four-Bestätigung. Die Quellrecords werden nicht verändert.
- Verifiziert: Im aktuellen `habits-dev/dev`-Stand `56ad2db` bestanden `node --test tests/*.test.mjs` (3 Testdateien) und `pnpm run build:firebase` (5.870 Module; PWA-SW erzeugt).
